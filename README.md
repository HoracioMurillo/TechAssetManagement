📋 Sobre el Proyecto Este portafolio no es un simple CRUD. Es una simulación de un entorno corporativo real diseñada para demostrar fundamentos sólidos de ingeniería de software. El objetivo principal fue construir un sistema robusto sin depender de cajas negras como ASP.NET Identity, implementando la seguridad, la autenticación y la auditoría manualmente para demostrar un entendimiento profundo del ciclo de vida de una aplicación web y el protocolo HTTP. 🎯 Características Clave (Nivel Enterprise) 🛡️ Seguridad "From Scratch": Sistema de Login y Registro manual utilizando BCrypt para hashing y gestión de Sesiones en el servidor. 🏗️ Arquitectura en Capas (N-Layer): Separación estricta de responsabilidades: Core: Entidades e Interfaces (Dominio). Infrastructure: Acceso a Datos (EF Core) y Servicios Externos. Web: Controladores y Vistas (MVC). 📝 Auditoría de Datos (Audit Log): Sistema de historial que rastrea automáticamente quién modificó un ticket, qué cambió (valores anterior/nuevo) y cuándo (Time-Travel Debugging). 📧 Integración SMTP: Servicio de notificaciones por correo electrónico con plantillas HTML profesionales para alertas de tickets y recuperación de contraseñas. ⚡ UX Asíncrona: Uso de AJAX y JSON para operaciones modales y búsquedas en tiempo real sin recargar la página. 👮 Control de Acceso (RBAC): Sistema de roles (Admin, Technician, User) con filtros de autorización personalizados ([AuthorizeUser]). 🛠️

Tecnologías y Patrones Categoría Tecnología / Patrón Backend C# .NET 8, ASP.NET Core MVC ORM Entity Framework Core (Code First) Base de Datos SQL Server 2019+ Frontend Razor Views, Bootstrap 5, JavaScript (jQuery), SweetAlert2 Seguridad BCrypt.Net, Session Management, Custom Middleware Patrones Dependency Injection (DI), Repository Pattern (via DbContext), Service Pattern (Email)

🧠 Desafíos Técnicos Resueltos

Sistema de Auditoría Automático Implementé una entidad TicketHistory que actúa como una bitácora inmutable. Cada vez que se edita un ticket, el controlador detecta los cambios (Dirty Checking) comparando el modelo entrante con el de la base de datos (usando AsNoTracking), registrando el cambio solo si hubo modificaciones reales.
Autenticación Manual vs Identity En lugar de usar Microsoft.Identity, construí un mecanismo de autenticación propio usando HttpContext.Session y Filtros de Acción (ActionFilterAttribute). ¿Por qué? Para demostrar capacidad de manejar cookies, seguridad de contraseñas y ciclo de vida de peticiones sin depender de frameworks automáticos.
Integridad de Datos en SQL Resolví el problema del "Multiple Cascade Path" de SQL Server configurando las relaciones en el OnModelCreating con Fluent API, usando DeleteBehavior.Restrict para evitar borrados accidentales en cascada que comprometan el historial. 🚀 Instalación y Despliegue
